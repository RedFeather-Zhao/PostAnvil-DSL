# 开发路线图

[文档中心](../README.md) · [项目首页](../../README.md)

> **评审日期**：2026-08-04  
> **评审基线**：PostAnvil 0.8.x 当前源码、公开 C++/Python API 与测试
> **文档性质**：规划建议，不代表已承诺的发布功能

## 评审口径

| 优先级 | 含义 |
|--------|------|
| **P0** | 近期：价值明确，可在不破坏现有语言模型的前提下落地 |
| **P1** | 近期重点：需稍多设计或基础设施，但应尽快启动 |
| **P2** | 中期：需先确定语义、接口或依赖项 |
| **P3** | 远期：涉及类型系统、模块系统或数据模型扩展 |
| **暂不建议** | 与当前设计冲突、收益不足或已有更清晰的组合方式 |

难度分为 **低 / 中 / 高**；涉及语法修改的条目还需重新生成 ANTLR 代码并补充回归测试。  
当前关键约束：换行是语句分隔符；`FILTER/GROUP/APPEND` 多行条件隐式按 `AND` 连接；值类型仅 `NUM/STR/BOOL/INST/ANY`；规则顺序编译并组成执行管道。

## 核心设计原则

评审所有建议时，以下三条原则是判断取舍的基准：

1. **声明式管道优先**：规则块职责单一，通过组合实现复杂逻辑。
2. **显式花括号、无缩进语义**：所有规则与控制流使用 `{ ... }` 明确块边界，换行符作为语义分隔符，空格/制表符仅用于排版。
3. **简洁值类型**：DSL 只处理 `NUM/STR/BOOL/INST/ANY` 五种值，暂不提供 `null`、数组或可选类型；批量操作由宿主 API 完成，`IMPORT/EXPORT` 仅传标量。

## 暂定依赖关系

仅保留已采纳或保留建议之间的核心依赖：

```text
错误信息增强 (S2) ───────────→ CLI / 编辑器诊断
trace 事件 (D1) ─────────────→ debug 计数 (D3) → 调试 CLI (D4) → 可视化标记（属性约定 D2）
函数签名预扫描 (S4) ─────────→ 前向引用 (S4)
CONST (E1) ─────────────────→ 符号表只读检查
```

## 下一迭代建议验收项（低风险集）


> **语法错误**：语法错误显示源码行、列、插入符和简化说明  
> **块注释**：支持非嵌套 /* ... */ 块注释  
> **安全查询**：_HAS_INST_INDEX / _HAS_INST_ID 已完成
> **内置函数可读性**：增加 overlap 描述性兼容别名  
> **C++ 测试与文档**：上述功能的 C++ 单元测试和用户手册示例  
> **性能基线**：建立 Scene 与 YOLO 转换性能基线 不承诺优化结果  
> 前向引用、_NEARBY_EDGE、CONST 和结构化 trace。  
> 所有新语法与内置函数保持大小写不敏感，并在 C++、Python、Android 绑定行为一致。
